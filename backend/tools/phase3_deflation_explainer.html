Phase 3 — Why we deflate the reported cumulative profit

The hyperparameter search inspects 9 combos per (pid, horizon) pair (depth ∈ {3, 5, 7} × min_leaf ∈ {20, 50, 100}) and picks the combo with the highest cumulative profit on the inner CV folds. Picking the max of 9 noisy estimates inflates the reported number — even if every combo has the same true profit, the maximum will overshoot by an amount that depends on (a) how many combos we tried, and (b) how noisy each combo's estimate is. This is the same failure mode that the probe-selection-bias diagnostic (Session 58.71p) found in v3.

This is not a bug in the search — searching is fine. The bug is reporting the raw maximum as if it were the true expected profit. The deflation factor corrects the reported number so reviewers see what the strategy is honestly worth, not the cherry-picked peak.

Setup: a toy (pid, horizon) example

Suppose the true cumulative profit of every combo is +5.0% (we don't actually know this — we're constructing a worked example). Each combo's measured profit on the inner CV is noisy: it's the true value plus a sample of Gaussian noise with standard error σ = 1.5% (derived from the variance across the 3 inner folds).

Here are the 9 simulated measurements (true = 5.0%, σ = 1.5%):

The naive hyperparam-search would report: "best combo found, cumulative profit = 7.2%". But the truth is 5.0%. The 7.2% is the lucky max of 9 draws — selection inflated it by 2.2 percentage points.

The formula

For N iid Gaussian draws with standard error σ, the expected gap between the maximum and the true mean is approximated by:

E[max − true] ≈ σ × √(2 × ln(N))

(This is the leading term of the expected maximum of N standard normals, a standard result in order statistics.) For our case:

N = 9                       # hyperparam combos
σ = 1.5%                    # per-combo standard error from inner CV variance
inflation = 1.5% × √(2 × ln(9))
          = 1.5% × √(2 × 2.197)
          = 1.5% × √4.394
          = 1.5% × 2.097
          ≈ 3.15%

So the deflated estimate is:

deflated_profit = raw_max − σ × √(2 × ln(N)) = 7.2% − 3.15% = 4.05%
Reported in Phase 3 output:
  • cumulative_profit_raw = 7.2% (what the search found)
  • cumulative_profit_deflated = 4.05% (selection-corrected estimate)
  • deflation_factor = 3.15 percentage points
  • n_combos_searched = 9 (for audit)
  • inner_cv_se = 1.5% (the σ that drove the deflation)
Both numbers go into the parquet. Phase 4 scorecard ranks on cumulative_profit_deflated; the raw number is kept for audit so we can see how much selection bias each profile was carrying.

Edge cases the formula handles cleanly

  • Low noise → low deflation. If σ is tiny (combos all measured very tightly), then σ × √(2 ln 9) is tiny, and raw ≈ deflated. The strategy was honestly good.
  • Big noise → big deflation. If σ is large (combos disagree wildly), the max is mostly luck and the deflation gap is large. The reported number tells you it was noisy.
  • Fewer combos → less deflation. If we searched only 3 combos instead of 9, √(2 ln 3) = 1.48 vs √(2 ln 9) = 2.10 — penalty scales with the number of trials.
  • Negative deflated profit. A strategy can have raw > 0 but deflated < 0 — meaning "we found a positive number but after correcting for how many we looked at, the strategy probably isn't profitable." Q0 hard gates should be applied to the deflated number.
What this does NOT do:
  • It does not correct for selection across pids or horizons (250 total pairs). Phase 4 scorecard handles cross-profile selection.
  • It does not correct for in-sample data snooping (the rule paths themselves were extracted from looking at the data). Purged WF + the 4-of-5-fold gate handle that.
  • It is not a Sharpe ratio deflation — for that see the Deflated Sharpe Ratio diagnostic from task #16. Phase 3 uses the simpler max-of-N correction since cumulative profit is the ranking metric, not Sharpe.
